# Uredo portfolio — Rust's concepts, from the simplest to the most complex

Twenty-five heavily commented pairs. Each folder holds `snippet.ure` (the Uredo source) and
`lowered.rs` (what the compiler emits, per `UREDO_LANGUAGE_SPEC_v0.4.md`).
Since 2026-09-11 every `lowered.rs` is **generated by the compiler** in `../../compiler` and kept
byte-identical by its golden test (`cargo test --test golden` there; `UREDO_GOLDEN_UPDATE=1`
regenerates after a deliberate change). Every `lowered.rs` is also a binary target of this package,
so the whole portfolio is checked with:

```bash
cargo build                       # all 25 compile
for b in [0-9]*/; do cargo run -q --bin ${b%/}; done
cargo test --bin 24_testing       # the test module
```

The comments in each snippet name the rule that applies (`D`-numbers are decisions in the
spec's §0 table; `§` are spec sections; `P1–P7` are the passing-mode rows of §10.2).

## Findings while writing the portfolio (spec feedback)

**Compiler pass (2026-09-11):** generating the files exposed three defects in the hand-written versions — string literals wrapped as `&"…"` (pre-D47), a `@derive(Copy)` type borrowed in topic 16, and `match *self` binding by value in topic 10 — and one spec gap, recorded as the G15 exception on D47: an argument for a *type-parameter* parameter is always borrowed, because `tag("n")` emitted verbatim would instantiate `U = str`. Topics 12 and 19 were briefly rewritten around block-bodied closures in call arguments while G9 was held; D51 (2026-09-11) admitted them and both topics are back in their natural form.

**Status (2026-09-11):** P1, P2 and P3 applied to the spec as D47 (§10.3, §9.9), D48 (§9.7) and D49 (§6.3, §29), revision 2026-09-11e. P4 was settled by D52 (type parameters and `impl Trait` pass by value, P8); the review's evidence: the corpus count of `impl Trait` parameters (1,793; `Into` 656, `FnOnce` 183, `IntoIterator` 162 … `Fn` 73) shows most are by-value sinks, so it is recorded as evidence on G16 in §38 rather than decided alone.

- **P1 — call-site borrow on an argument that is already a reference expression.** §10.3 says an
  inserted `&` on an argument that is already a reference yields `&&T`, "which Rust coerces". That is
  true for `&&str` and `&&[T]` (deref coercion) but **false for a reference to an array**: `first_byte(b"hi")`
  with `bytes: [u8]` would lower to `first_byte(&b"hi")`, i.e. `&&[u8; 2]`, which needs a deref *and* an
  unsize and does not compile. The decidable fix (no types needed): when the argument is syntactically a
  reference expression — `&e`, `&mut e`, a string or byte-string literal, or a binding whose declared type
  is an explicit `&T` — emit it verbatim. Topic 23's lowering does this. This narrows the G15 question
  to the syntactic case the panel said was safe.
- **P2 — `str` return with no borrowed parameter** (topic 03): §9.7's elided `str` return has nothing to
  borrow from, so `&'static str` must be written. The spec should say so explicitly.
- **P3 — inline `if` expression after `=` on one line** (topic 03, `n = if c: a else: b`): legal under
  D34's `else` anchor only because both bodies are inline; the formatter rule in §29 should show it.
- **P4 — `impl Trait` parameters** (topic 12): `f: impl Fn(u32) -> u32` lowers to `&impl Fn` under P3 and
  callers pass `&double`; it works, but it is the G16 review item in practice.

## `uredo lint` over the portfolio

`uredo lint docs/portfolio` reports one finding, deliberately: topic 05 declares
`consume_number(n: take u64)` to show that `take` on a known-Copy type copies rather than moves,
which is exactly what `redundant_take` is for (§29.1). Topic 21 carried a second one — a `take` on a
type parameter left over from before D52 — and it was dropped. Everything else in the portfolio, the
corpus and the examples is clean.
